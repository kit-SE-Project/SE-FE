# 서버 올데이 웹 통합 기록

기준: SE-FE `f835fc9`, serverAllDay_FE SSO `84c9c8b`, 대여 백엔드 계약 `fa1777c`. 작업 브랜치: `codex/server-allday-integration`.

## 구성

- `apps/server-allday`에 브라우저용 대여 프론트 소스를 추가했다. 기존 로컬 카테고리 보완도 이 복사본에 반영했다. 앱스토어·네이티브 패키지 생성 설정과 별도 백엔드를 찾는 Windows 실행기는 포함하지 않는다.
- React 18 게시판과 React 19 대여 웹은 각각 설치·빌드한다. pnpm workspace에서 대여 폴더를 제외하고 자체 npm lockfile을 유지한다.
- Expo의 운영 자산 경로는 `/allday`다. 게시판 메뉴는 일반 링크로 `/allday/` 문서를 연다. 대여 로고는 SE 게시판 홈으로 돌아간다.
- `/allday/sso`는 기존 게시판 SSO 중계가 처리하며 시작·콜백과 기타 API는 기존 `/api/v1` 계약을 유지한다.
- 운영 Nginx 구성과 Node 로컬 미리보기에서 기존 백엔드의 SSO 루트 복귀 응답만 `/allday/`로 보정한다. 이 보정이 적용되는 프록시를 거쳐야 한다. 백엔드에 별도 복귀 경로 설정이 구현되면 프록시 보정은 호환 목적으로 남거나 제거할 수 있다.

## 인증 처리 보완

- `/me`의 회원 ID가 바뀌면 기존 API 클라이언트의 늦은 응답을 무효화하고 대여·접속 화면·모달을 비운 뒤 세션을 다시 확인한다.
- 로그아웃 응답 손실 뒤 서버가 비로그인이라고 확인하면 기존 사용자 화면을 제거한다. 세션이 유효하면 실패를 안내하고, 인증 서비스 503을 로그아웃 성공으로 간주하지 않는다.
- 기존 세션이 유효해도 SSO expired/unavailable 복귀 안내를 처리하고 쿼리를 제거한다.
- 게시판의 만료 응답이 늦게 도착했을 때 이미 새 access token이 있으면 이를 재사용해 한 번 재요청한다. 동시 refresh 공유와 재시도 제한은 유지한다.
- 일반 개발 비밀번호 인증과 운영 SSO 경로를 분리한다. 운영 데이터는 실제 API로만 읽고 변경한다.

## 배포 시 필요한 값

| 위치 | 설정 |
| --- | --- |
| 게시판 빌드 | 기존 `REACT_APP_API_ENDPOINT` 등, 선택적 `REACT_APP_ALLDAY_ORIGIN` |
| 대여 빌드 | `EXPO_PUBLIC_SEBOARD_SSO_ENABLED=true` — 통합 빌드 명령에서 지정 |
| 웹 컨테이너/로컬 미리보기 | `ALLDAY_API_UPSTREAM` — 실제 대여 백엔드 오리진 |
| 대여 백엔드 | 같은 공개 `ALLDAY_SSO_PUBLIC_ORIGIN`·`CORS_ORIGIN`, `/allday/sso` portal URL |
| SE 백엔드 | 같은 공개 도메인의 `/api/v1/sso/callback` 콜백 URL |
| 양 백엔드 | 기존 내부 통신 주소·공유 비밀 및 DB/Redis 설정 |

기존 운영 Ingress의 전체 경로와 서비스 DNS는 로컬 코드만으로 확정하지 않았다. `/api/v1` 점유와 프록시 라우팅을 배포 담당자가 확인해야 한다.

## 확인 기록

- 대여 웹 자동 검사 142개, 게시판 인증·오류 복구 검사 8개, 통합 경로/쿠키 API 전달·빌드 파일 유지 검사 7개(총 157개) 통과.
- 두 웹의 production 빌드 성공. 대여 HTML이 `/allday/_expo/...` 자산을 참조하며, 게시판의 최종 빌드에 실제 SE API 주소를 반영했다. 통합 Docker 빌드와 CI는 로컬에서 확인한 Node 22.14.0을 사용하며 의존성은 프로젝트별로 유지한다.
- 게시판 테스트는 실제 axios 전송 어댑터를 제어하며, SSO 브라우저 파라미터 검사는 별도의 Node 환경에서 수행한다. 전체 프론트/UI를 실제 운영 서버에 로그인해 검사했다는 의미는 아니다.
- 실제 게시판 API는 `https://seboard.site/v1`, 알림은 `https://seboard.site/alarm`임을 공개 웹 번들에서 확인했다. `/v1/menu`는 200 JSON, 메뉴 7개를 반환했다. API 주소가 비었을 때 게시판 HTML을 응답으로 읽고 화면이 멈추던 기본 설정 문제를 수정했다.
- 공개 운영 OpenAPI에 `/allday/sso/authorize`는 아직 표시되지 않는다. 배포된 SE 백엔드가 SSO 작업 브랜치를 포함하는지 확인이 필요하다. Spring Security의 `/formLogin`은 컨트롤러 OpenAPI에 없을 수 있으므로 목록 부재만으로 로그인 불가로 판단하지 않는다.
- 기존 로컬 대여 설정의 ngrok 주소는 `/health`가 404였고, 로컬 18082의 대여 API 연결도 확인되지 않았다. 대여 `ALLDAY_API_UPSTREAM`은 실제 실행/배포 주소로 지정해야 한다.
- Docker 엔진이 실행되지 않아 컨테이너 이미지 전체 빌드·기동은 미수행이다. 실제 서버 로그인·예약·VM 반환은 운영 구성 확인 후 검증한다.
- 공식 Windows Nginx로 실제 배포 템플릿의 문법, 게시판/대여/SSO 중계 분기, 누락 자산 404, 콜백 성공·만료·실패의 `/allday/` 복귀 및 쿠키 전달, 내부 API 경로 차단을 별도 임시 포트에서 확인했다. 검사 도구와 결과는 Git에서 제외한 로컬 폴더에 둔다.
- 사용자 직접 입력 후 실제 SE API로 로그인된 회원 표시와 로그아웃 버튼, 게시판 메뉴·게시물 조회를 확인했다. 실제 계정 정보·토큰·비밀번호는 문서에 기록하지 않는다.
- 게시판의 서버 대여 링크로 `/allday/`가 열리는 것을 확인했다. 대여 백엔드는 현재 실행 주소에 연결되지 않아 세션 확인이 503 오류로 표시된다. 게시판 로그인 성공을 대여 SSO 성공으로 취급하지 않는다.
- 사용자 요청에 따라 기존 ‘서버대여’ 메뉴와 원래 목적지를 유지한다. 신규 웹은 데스크톱·모바일 모두 ‘서버 대여 (테스트중)’으로 표시하고 `/allday/`로 이동한다. 기존 항목을 이름으로 필터링하지 않는다.

## 대여 진입·게시판 복귀 점검 및 보완

- 안정된 빌드에서 대여 진입 후 뒤로 가기로 게시판 내용이 다시 나타나는 것은 확인했다. 과거 빈 화면의 원인을 하나로 확정하지 않는다. 다만 게시판 직접 빌드는 공개 폴더를 먼저 비우며, 이전 HTML이 참조하는 화면 파일이 사라지는 조건을 확인했다.
- 통합 루트의 `npm run build:board`, `npm run build:allday`는 임시 폴더에서 빌드하고 성공한 결과만 반영한다. 자산을 먼저 복사하고 HTML을 마지막에 교체하며 이전 해시 파일을 유지한다. 실행 중인 미리보기에서는 이 명령을 사용한다. 새 컨테이너 배포 간 이전 자산 유지까지 보장하는 변경은 아니다.
- 실제 빌드 중 게시판 HTML과 기존 JavaScript가 200으로 제공되는 것을 확인했다. 별도 HTTP 회귀 검사에서도 기존 페이지 자산 유지와 실패한 빌드의 미반영을 검증했다.
- 초기 화면에 로딩 안내를 추가했다. 스크립트 로드 실패·React 렌더 오류·게시판 API 오류 시 각각 복구 안내를 표시한다. 로그인 정보를 지우지 않는다.
- 대여 백엔드 연결 실패 화면에 ‘SE 게시판으로 돌아가기’를 추가했다. 실제 브라우저에서 새로고침 → 테스트 대여 메뉴 → 연결 실패 안내 → 복귀 버튼 → 게시판 내용 표시를 확인했다. 브라우저 뒤로 가기로 복귀하는 동선도 확인했다.
- 현재 대여 백엔드에는 연결되지 않는다. 실제 SSO 완료·예약·접속 정보·반납 통합 검증은 미완료이며, 프론트 자동 검사 통과와 구분한다.
