# 개발 백로그

## 카테고리 관리 — API 계약 확인 및 연동 보완 (2026-11-11)

최신 백엔드 `855ca5d0c2541e30786054b16bee10510c916017`에서 카테고리 API 문서·관리자 CRUD 구현·검증 규칙을 확인했다. 현재 관리자 UI의 API 호출 경로·본문은 이 구현과 일치한다. 성공·실패 안내, 목록 갱신 실패 시 읽기만 재시도, 버전 충돌 후 재선택 및 서버 행의 최신 카테고리명 표시를 보완했다. 실제 배포 API를 통한 관리자 계정 CRUD 확인은 별도 실행 환경에서 필요하다.

과거 요청 중 **서버 추가 폼 안에서 바로 카테고리를 생성하고 자동 선택하는 UX**는 현재 별도 구현하지 않았다. 관리자 카테고리 관리에서 생성한 항목은 서버 추가·수정 폼의 목록으로 재조회된다.

## 과거 기록 — 카테고리 관리 보류 (2026-10-27)

사용자 요청에 따라 이번 작업을 보류했다. 현재 프론트엔드는 백엔드 카테고리 목록 조회와 서버 추가·수정 시 기존 카테고리 선택만 제공한다. 이번에 착수한 미완성 코드는 반영하지 않았다.

- 서버 추가·수정 폼에서 카테고리 추가 및 새 카테고리 자동 선택
- 관리자 대시보드에서 카테고리 이름·설명 수정
- 삭제 대상 확인 및 확인 후 삭제
- 서버에서 사용 중인 카테고리 삭제 방지
- 입력 검증, 중복 제출 방지, 성공·실패 안내와 목록 동기화
- 현재 등록 API `POST /api/v1/admin/categories` 연결
- 최신 백엔드 담당자와 수정·삭제 API 계약 및 동시 수정(version) 처리 확정

확인한 프론트 전달 계약 `tests/contracts/public-api.json`에는 카테고리 조회·등록만 있고 수정·삭제 API는 없다. 재개 시 실제 사용하는 최신 백엔드 소스와 계약을 확인한다. 목업 저장으로 대체하지 않는다.
