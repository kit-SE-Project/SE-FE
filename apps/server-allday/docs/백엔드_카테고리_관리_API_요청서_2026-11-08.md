# Server AllDay 관리자 카테고리 관리 API 요청서

작성일 2026-11-08 · 백엔드 개발 담당자 전달용

**2026-11-11 확인:** 요청했던 카테고리 API는 백엔드 `855ca5d0c2541e30786054b16bee10510c916017`에 문서와 구현이 있습니다. 아래 내용은 당시 요청 기록이며, 현재 연결 계약·검증 범위는 [카테고리 API 연동 확인](카테고리_API_연동_확인_2026-11-11.md)에 정리했습니다.

관리자 대시보드에 카테고리 목록, 추가·수정 양식, 삭제 확인 화면을 준비했습니다. 목록은 기존 조회 API로 표시하며, 저장과 삭제 버튼은 API 계약이 확정되면 연결하겠습니다. 아래 제안의 적용 가능 여부와 실제 요청·응답 형식을 알려주세요.

## 필요한 API

| 동작 | 확인한 현재 상태 | 요청 사항 |
| --- | --- | --- |
| 목록 조회 | `GET /api/v1/categories`에서 `id`, `name`, `description`, `version`을 반환합니다. | 관리 화면에는 서버가 아직 배정되지 않은 카테고리도 필요합니다. 기존 API로 전체 조회가 가능한지, 관리자용 `GET /api/v1/admin/categories`가 필요한지 확인해 주세요. 현재 실장비 시험 모드의 기존 조회는 서버가 연결된 카테고리만 반환합니다. |
| 추가 | `POST /api/v1/admin/categories`가 있으며 `Idempotency-Key`를 사용합니다. 성공 시 `201`과 생성된 카테고리를 반환합니다. | 기존 계약을 그대로 사용해도 되는지 확인해 주세요. |
| 수정 | 확인한 백엔드에 수정 경로가 없습니다. | `PATCH /api/v1/admin/categories/{id}`를 제안합니다. 이름·설명과 `expectedVersion`을 받아 수정하고, 성공 시 `200`과 갱신된 카테고리 및 `version`을 반환해 주세요. |
| 삭제 | 확인한 백엔드에 삭제 경로가 없습니다. | `DELETE /api/v1/admin/categories/{id}`를 제안합니다. `expectedVersion`을 받아 삭제하고, 성공 시 `204`를 반환해 주세요. |

수정 요청 본문 예시입니다. 이름은 필수이며 최대 100자, 설명은 선택이며 최대 2,000자로 기존 등록 규칙에 맞췄습니다. 설명을 지울 때 빈 문자열과 `null` 중 어떤 값을 보내야 하는지도 알려주세요.

```json
{
  "name": "GPU 서버",
  "description": "딥러닝 학습용 장비",
  "expectedVersion": 2
}
```

## 함께 결정할 정책

- **권한과 재시도**. 추가·수정·삭제는 백엔드에서 관리자 권한을 확인해 주세요. 수정·삭제에 `Idempotency-Key`가 필요한지, 삭제 버전 값을 요청 본문으로 보내면 되는지도 확인 부탁드립니다.
- **연결된 서버가 있는 카테고리**. `server_node.category_id`가 카테고리를 참조합니다. 연결된 서버와 과거 대여 이력을 보존할 수 있도록, 사용 중인 카테고리는 `409`로 차단하고 서버를 다른 카테고리로 옮긴 후 삭제하는 방식을 제안합니다. 이미 삭제 처리된 서버가 참조하는 경우를 포함해 실제 차단 기준과 논리 삭제 적용 여부를 알려주세요.
- **프론트에서 표시할 오류**. 중복 이름, 다른 관리자가 먼저 수정한 버전 충돌, 연결된 서버로 인한 삭제 차단을 구분할 수 있는 오류 코드를 부탁드립니다. 버전 충돌 시 프론트는 목록을 다시 조회할 수 있습니다. 존재하지 않는 카테고리(`404`)와 입력 오류(`422`)도 포함해 실제 응답 예시를 공유해 주세요.

연동 가능한 테스트 환경과 최신 OpenAPI 또는 요청·응답 예시를 공유해 주시면, 미사용 카테고리의 추가 → 수정 → 삭제와 서버가 연결된 카테고리의 삭제 차단까지 확인하겠습니다.
